八丁堀・新富町のパーソナルジム「D/LIGHT GYM」の**体験トレーニング申込に特化した1枚完結のランディングページ**。
広告・SNS・チラシQRなどからの流入先を想定しています。

本家サイト（`../ホームページ作成/site/`）の内容とデザインをもとに作成していますが、
**CSS・JS・画像まで含めてこのフォルダだけで完結する自己完結型**です。本家を編集しても、このLPには影響しません（逆も同じ）。

### Google広告のコンバージョンタグ（設定済み）

`assets/js/analytics.js` の冒頭に入っている。**A案・B案の両方がこの1本を読むので、
ここを直せば2ページとも同時に変わる。**

```
ADS_CONVERSION_ID = 'AW-18357784683'
ADS_LABEL_RESERVE = 'peb6CK742OscEOug1rFE'   体験予約ボタン（Squareへのリンク）
ADS_LABEL_LINE    = 'Y0arCOnuzescEOug1rFE'   公式LINEへのリンク
```

**Google広告が案内するスニペットを `<head>` にそのまま貼らないこと。**
このLPは `analytics.js` が gtag.js を1本だけ読み込んでいる。案内どおりに貼ると
2本目が読まれ、さらにスニペット側のクリック処理とこちらの処理が二重になって
**コンバージョンが2倍に膨らむ**。IDはこのファイルに置き、送信もここから行う。
`index.html` の7行目にも同じ注意書きを入れてある。

アクションを増やすときは、ラベルの定数を足して `adsConversion(ラベル)` を
該当のクリック分岐から呼ぶ。**呼ぶ場所は1か所だけにすること。**

動作確認（2026/09/01・A案B案の両方で実クリック）：

| 押したもの | 送られるもの |
|---|---|
| 体験予約ボタン | `reserve_click` → `generate_lead` → `conversion`（`…/peb6CK742OscEOug1rFE`）各1回 |
| LINEリンク | `line_click` → `conversion`（`…/Y0arCOnuzescEOug1rFE`）各1回 |

`config` は `G-LESJ5MJNHV` と `AW-18357784683` の2つ。
こちらが挿入する gtag.js は1本だけ（もう1本はgtag.js自身がAW用に足すもので、正常）。

予約もLINEもリンクは全部 `target="_blank"` で別タブが開くため、送信が途中で切れることはない。
**同じタブで遷移する作りに変えたら、`event_callback` で待つ処理が必要になる。**

**金額は送っていない。** この時点で分かるのは「予約ページを開いた」ことだけで、
体験の5,000円が入ったわけではない。仮の金額を送ると、その数字で入札が最適化されてしまう。
値を入れるならGoogle広告のコンバージョンアクション側で「デフォルト値」として設定する。

**このコンバージョンは「予約完了」ではなく「予約ページを開いたクリック」。**
実際の予約はSquare（`book.squareup.com`＝別ドメイン）で起きるので、このLPからは見えない。
Squareにトラッキングコードを貼る欄があるか分かるまで、この数字は
**実際の予約より多く出る**前提で見ること。LINEも同じで、友だち追加ではなく
LINEを開いたクリックを数えている。

### 2. UTM の付け方

LP側は、着地URLの `utm_*` / `gclid` / `fbclid` を **Square の予約URLに自動で引き継ぐ**（`assets/js/lp.js` の末尾）。
あわせて `lp_cta`（hero / results / trial / price / cta_band / mobile_bar など）も付くので、
「どの広告の、どのボタンから予約されたか」まで追える。

広告のリンク先URLの例：

```
https://dlightgym.com/lp/trial/?utm_source=google&utm_medium=cpc&utm_campaign=trial_2608_pain&utm_content=headline_a
```

命名は次で統一する。

- `utm_source`：`google` / `facebook` / `instagram` / `flyer` / `line`
- `utm_medium`：`cpc`（広告）/ `qr`（チラシ）/ `profile`（SNSプロフィール）
- `utm_campaign`：`trial_年月_訴求`（例 `trial_2608_pain`、`trial_2608_golf`）
- `utm_content`：クリエイティブの識別名

**要確認：** Square が未知のクエリパラメータを受け取っても予約ページが正常に開くか、実機で1回試すこと。
開かない場合は `lp.js` 末尾のブロックを削除すれば元に戻る。

## CSS・JSを直したあとに必ずやること

スマホのブラウザは CSS を強くキャッシュするため、ファイルを直しても
古いままの見た目が残る（実際にSafariで発生した）。
**`index.html` と `lp-a.html` の `?v=` の日付を必ず更新すること。**

```bash
# 例：?v=20260827a → ?v=20260828a に一括置換

```

## FAQ を増やす・減らす・書き換えるとき

`index.html` の `<head>` にある **FAQPage の構造化データも、同じ数・同じ文面に直すこと。**
Googleは「ページに表示されていない内容」が書かれた構造化データを無視するか、
悪質な場合は手動対策の対象にする。現在は7問で一致している。

`lp-a.html` にも別に10問ぶんの FAQPage が入っているが、こちらは比較用に残しているだけ。

## 見出しの「残り◯ヶ月」

ヒーローの見出しにある数字は、`lp-b.js` が**今日の日付から入れ直している**（`[data-months-left]`）。
手で書いたままだと月をまたいだ瞬間に嘘になるため。当月は数えない（8月なら9〜12月で4ヶ月）。
12月だけは0にせず1と出す。JSが動かない場合はHTMLに書いてある `4` がそのまま出る。

**この見出しは年始がもっとも効く。** Google広告を回すなら1月に予算を寄せる価値がある。

## 文字サイズ

読み手が40〜50代なので、**2026年8月に全体を1px上げている**（`lp-b.css` の
`font-size` 93宣言すべて。`clamp()` は最小・最大の両方を+1px）。

  バーの位置が違うので、そのままでは手が切れる（旧カットは 20/19・Y=44%）。

### 枠が縦長（20/21）である理由

**「ラットプルダウンをしている」と分かるのに必要な範囲が、縦に長いから。**

写真（1023×1537）の中で要るのは **縦19%（トレーナーの頭の上）〜縦80%（お客様が
バーを握る左手）の61%**。ここが入らないと、バーが切れて「ただ座っている写真」になる。

枠は縦長、写真も縦位置なので、`cover` で入れると**左右は全部入り、上下だけが切れる**。
枠に残る縦の割合は次の式で決まる。

```
残る割合 = (枠の高さ ÷ 枠の幅) × (1023 ÷ 1537)
        = (枠の高さ ÷ 枠の幅) × 0.666
```

61%を残すには高さが幅の0.92倍以上。**横長の枠では物理的に入らない。**

実際には `aspect-ratio:20/21`（高さ＝幅の1.05倍）まで伸ばしてある。0.92でぴったりに
しない理由は、**下辺の斜め切り（`clip-path`）が右下を10%削る**から。ぎりぎりに詰めると、
バーを握る手が斜めに食われる。1.05なら縦16.6%〜86.4%が残り、枠の中での位置は：

| 写したいもの | 元画像の縦位置 | 枠の中の位置 | 斜め切りの線 |
|---|---|---|---|
| トレーナーの頭の上 | 19% | 上から3.5% | — |
| お客様の右手（時計側） | 72% | 79.3% | 90.7% ✅ |
| お客様の左手 | 80% | 90.8% | 97.5% ✅ |

比が固定なので、**どの画面幅でも写り方がまったく同じ**になる。実測（2026/09/01）：

| 画面幅 | 枠 | 残る範囲 |
|---|---|---|
| 320px | 320×336 | 16.6〜86.4% |
| 390px | 390×410 | 16.6〜86.4% |
| 599px | 599×629 | 16.6〜86.4% |
| 768px | 560×588 | 16.6〜86.4% |
| 900px〜 | 560×588 | 16.6〜86.4% |

**やってはいけないこと。**

- **高さを `svh` や固定pxにする。** 画面が低いときや幅が広いときだけ枠が平たくなり、
  そこだけバーが切れる。高さは必ず `aspect-ratio` で幅から出すこと。
- **枠を横長にする（幅を広げて高さを据え置く）。** 同じ理由でバーが切れる。

**幅は写り方に影響しない。** 写り方は `aspect-ratio` と `object-position` だけで決まる。
PCの560pxという値は、純粋に「写真の存在感」と「コピーの位置」の取り合いで決めた数字。
広げれば高さも1.05倍で伸びて、そのぶんコピーが下がる。

### 写真を差し替えたときにやること

**カットが変わったら、必ず縦位置を測り直すこと。** 2026/09/01の差し替えでは、
同じ撮影の別カットに変えただけでバーの位置が下がり、旧設定（20/19・Y=44%）のままだと
手が切れた。`aspect-ratio` と `object-position` の両方を調整し直している。

測り方は、パーセントの目盛りを重ねた画像を作るのが早い。

```python
from PIL import Image, ImageDraw
im = Image.open('assets/img/hero-lat-pulldown.webp').convert('RGB'); w,h = im.size
d = ImageDraw.Draw(im)
for pct in range(0,101,5):
    y = int(h*pct/100); d.line([(0,y),(w,y)], fill=(255,0,0), width=3)
    d.text((8,y+4), f'{pct}%', fill=(255,255,0))
im.save('/tmp/grid.png')
```

そのうえで、**斜め切りまで再現した仕上がりを画像で出してから決める**。
ブラウザで確認する前にここで弾いたほうが早い。

```python
def render(pw, ph, Y, name):          # pw/ph=枠の寸法, Y=object-position の Y
    scale = pw/IW; sh = IH*scale; off = (sh-ph)*Y
    img = src.resize((pw,int(sh))).crop((0,int(off),pw,int(off)+ph))
    mask = Image.new('L',(pw,ph),0)
    ImageDraw.Draw(mask).polygon([(0,0),(pw,0),(pw,int(ph*.9)),(0,ph)], fill=255)
    out = Image.new('RGB',(pw,ph),(255,255,255)); out.paste(img,(0,0),mask); out.save(name)
```

X（50%）は結果に影響しない（左右は全部入るので）。

### PCではコピーが下がる

写真を大きくするとコピーがそのぶん下へ動く。現在の寸法で「どうせやるなら今から」の
下端が **912px**。1920×1080では画面内に入るが、**1440×900級のノートでは折り返しの下**に
なる（ブラウザのバーを引くと実表示は800px前後のため）。**スマホは影響なし**
（390pxで見出しが540px、折り返しは844px）。

ファーストビューはPCも1カラムという指示があるので、いまはこの形。
コピーを上げたい場合は、PCのパネル幅を縮めるか（写り方は変わらない）、
PCだけ2カラム（本家HPと同じ左右振り分け）にするかの二択になる。

### ヘッダーの高さ（`--hd-h`）

ヘッダーは固定配置なので、写真パネルは自力でその高さぶん下がる必要がある。
ところが**ヘッダーの高さは中身の折り返しで69px〜91pxの間で変わり、折り返す幅も
端末の文字サイズ設定で動く**。メディアクエリで決め打ちすると必ずどこかの幅で
「写真がヘッダーの裏に潜る」か「上に白い帯が残る」になる（実際、340pxで切っても
341pxで21px潜った）。

そこで `lp-b.js` が実測値を `--hd-h` に入れ、`.fv` の `padding-top` がそれを使う。
フォントが後から届くと高さが変わるので `document.fonts.ready` でもう一度測っている。
**JSが動かなかったときのフォールバックは94px（いちばん高いとき）。**
写真がヘッダーの裏に潜るより、白い余白が少し残るほうが軽い失敗なので、大きいほうへ倒してある。

- **ファーストビューはPCも1カラム**（2026年8月に2カラムから変更）。
  左右に振り分けると写真だけが右に離れて見えるため、写真パネルを中央に置き、
  その下にコピーを中央寄せで積む形にした。`.fv__in` は `max-width:760px` で行長を抑えている。

## 編集時のルール

- **グローバルナビは意図的に置いていません。** LPは離脱を防ぐため、ヘッダーはロゴ＋予約ボタンのみ。
  ナビを足したくなったら、それは本家サイト側の役割です。
- **色・フォント・余白は `lp.css` の `:root` を触る。** 個別要素にハードコードしない。
- 既存クラス（`.section` / `.sec-head` / `.grid` / `.card` / `.split` / `.stage` / `.prog` / `.flow` /
  `.trial-card` / `.ptable` / `.acc` / `.cta-band` / `.notes` / `.trouble` / `.reason` / `.num-card` /
  `.made` / `.rec` / `.assure` / `.sim` / `.campaign` / `.proof`）で
  組めないか確認してから新しいクラスを足す。
- スクロール表示アニメーションは `data-reveal` 属性を付けるだけで効く。
- 日本語の見出しは明朝（`--f-serif`）、本文はゴシック（`--f-sans`）、英字は Jost（`--f-en`）。
- 画像を追加するときは軽量化してから置く（長辺1200px / JPEG品質72 目安、ヒーローのみ1600px）。
  `sips -s format jpeg -s formatOptions 72 -Z 1200 in.jpg --out out.jpg`

**勝手に数字や実績を作らないこと。** 不明な値は「公式LINEでお問い合わせください」に寄せます。

- 体験トレーニング 80分 5,000円（税込）／入会金 通常 33,000円（税込）

  キャンペーンを終了するときは、この2枚のカードを 70,400円／89,100円 に戻し、`sim__after` の「入会金が無料なので〜」の一文も消すこと。
- **ビフォーアフターの写真は本人の許諾済み。**「効果には個人差があり、結果を保証するものではありません」の注記を必ず残すこと（`.ba__note`）。

- 会員データの円グラフ（年代・入会時の経験・目的）は本家トップと同じ構成比で、**元画像から再現した概算**です。そのため「※構成比は概算です」の注記を必ず残すこと。正確な数値が手に入ったら差し替えます。
