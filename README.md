# D/LIGHT GYM 体験トレーニング LP

八丁堀・新富町のパーソナルジム「D/LIGHT GYM」の**体験トレーニング申込に特化した1枚完結のランディングページ**。
広告・SNS・チラシQRなどからの流入先を想定しています。

本家サイト（`../ホームページ作成/site/`）の内容とデザインをもとに作成していますが、
**CSS・JS・画像まで含めてこのフォルダだけで完結する自己完結型**です。本家を編集しても、このLPには影響しません（逆も同じ）。

```

### ファーストビューの並び順（スマホとPCで違う）

`grid-template-areas` で5ブロックを入れ替えている。**この並びには理由がある。**

| | スマホ | PC（900px〜） |
|---|---|---|
| 順番 | 見出し → 写真 → サブコピー → **料金とCTA** → 独自性・信頼材料 | 左：見出し → サブ → 独自性・信頼 → 料金 → CTA／右：写真 |

スマホで料金とCTAを前に出しているのは、公開前チェックの
**「タイトル・料金・CTAが早い段階で見えること」**を満たすため。
指示書の並び（サブ→独自性→信頼→オファー→CTA）のまま縦に積むと、
390×844の端末で**料金が945px・CTAが1117px**の位置になり、どちらも最初の画面に入らなかった。
入れ替え後は**見出し169px・料金723px・CTA798px**。

PCを2カラムにしているのも同じ理由。1カラムだと正方形の写真の高さぶんコピーが下がり、
1440×800のノートでCTAが折り返しの下に落ちる。2カラムなら
**場所113px・コピー246px・料金680px・CTA786px**で、指示書の
「一般的な画面サイズで、コピー・場所・体験料金・CTAまで見える」を満たす。

**数字を変えたら、390×844と1440×800の両方で測り直すこと。**

### 1. 計測ID（設定済み）

`assets/js/analytics.js` 冒頭の `GA_MEASUREMENT_ID` に `G-LESJ5MJNHV` を設定済み。

**`positionOf()` を触るときの注意。** この関数が `reserve_click` / `generate_lead` の

書いていないほうのLPでCTAの内訳が取れなくなる。**
実際に2026年8月にこれが起きていて、B案10個のCTAのうち6個が `body` に落ちていた。
どれにも当てはまらないときは、囲っている `section` の id をそのまま使う。

確認方法：ブラウザのコンソールで
document.querySelectorAll('a[href*="book.squareup.com"]').length
と、GA4のDebugViewで position が全部バラけているかを見る
```


### Google広告のコンバージョンタグ（設定済み）

`assets/js/analytics.js` の冒頭に入っている。**A案・B案の両方がこの1本を読むので、
ここを直せば2ページとも同時に変わる。**

```
ADS_CONVERSION_ID = 'AW-18357784683'
ADS_LABEL_RESERVE = 'peb6CK742OscEOug1rFE'   体験予約ボタン（Squareへのリンク）
ADS_LABEL_LINE    = 'Y0arCOnuzescEOug1rFE'   公式LINEへのリンク
```

**Google広告が案内するスニペットを `<head>` にそのまま貼らないこと。**
このLPは `analytics.js` が gtag.js を1本だけ読み込んでいる。案内どおりに貼ると
2本目が読まれ、さらにスニペット側のクリック処理とこちらの処理が二重になって
**コンバージョンが2倍に膨らむ**。IDはこのファイルに置き、送信もここから行う。
`index.html` の7行目にも同じ注意書きを入れてある。

アクションを増やすときは、ラベルの定数を足して `adsConversion(ラベル)` を
該当のクリック分岐から呼ぶ。**呼ぶ場所は1か所だけにすること。**

動作確認（2026/09/01・A案B案の両方で実クリック）：

| 押したもの | 送られるもの |
|---|---|
| 体験予約ボタン | `reserve_click` → `generate_lead` → `conversion`（`…/peb6CK742OscEOug1rFE`）各1回 |
| LINEリンク | `line_click` → `conversion`（`…/Y0arCOnuzescEOug1rFE`）各1回 |

`config` は `G-LESJ5MJNHV` と `AW-18357784683` の2つ。
こちらが挿入する gtag.js は1本だけ（もう1本はgtag.js自身がAW用に足すもので、正常）。

予約もLINEもリンクは全部 `target="_blank"` で別タブが開くため、送信が途中で切れることはない。
**同じタブで遷移する作りに変えたら、`event_callback` で待つ処理が必要になる。**

**金額は送っていない。** この時点で分かるのは「予約ページを開いた」ことだけで、
体験の3,300円が入ったわけではない。仮の金額を送ると、その数字で入札が最適化されてしまう。
値を入れるならGoogle広告のコンバージョンアクション側で「デフォルト値」として設定する。

**このコンバージョンは「予約完了」ではなく「予約ページを開いたクリック」。**
実際の予約はSquare（`book.squareup.com`＝別ドメイン）で起きるので、このLPからは見えない。
Squareにトラッキングコードを貼る欄があるか分かるまで、この数字は
**実際の予約より多く出る**前提で見ること。LINEも同じで、友だち追加ではなく
LINEを開いたクリックを数えている。

### 2. UTM の付け方

LP側は、着地URLの `utm_*` / `gclid` / `fbclid` を **Square の予約URLに自動で引き継ぐ**（`assets/js/lp.js` の末尾）。
あわせて `lp_cta`（hero / results / trial / price / cta_band / mobile_bar など）も付くので、
「どの広告の、どのボタンから予約されたか」まで追える。

広告のリンク先URLの例：

```
https://dlightgym.com/lp/trial/?utm_source=google&utm_medium=cpc&utm_campaign=trial_2608_pain&utm_content=headline_a
```

命名は次で統一する。

- `utm_source`：`google` / `facebook` / `instagram` / `flyer` / `line`
- `utm_medium`：`cpc`（広告）/ `qr`（チラシ）/ `profile`（SNSプロフィール）
- `utm_campaign`：`trial_年月_訴求`（例 `trial_2608_pain`、`trial_2608_golf`）
- `utm_content`：クリエイティブの識別名

**要確認：** Square が未知のクエリパラメータを受け取っても予約ページが正常に開くか、実機で1回試すこと。
開かない場合は `lp.js` 末尾のブロックを削除すれば元に戻る。

**新規会員募集キャンペーン（2026年12月31日まで）。内容は2つ。**

1. **入会金 33,000円（税込）→ 0円** ／ このページからのご予約限定

景表法（二重価格表示）の観点から、**通常価格 33,000円と適用条件「このLPからのご予約限定」は
必ず併記**したまま運用すること。条件を落として「入会金無料」だけを出さない。

「定員に達した場合は期間内でも受付を終了する場合があります」と書いてあるので、
**実際に終了するときは、その時点でこの文言ごと落とすこと。**

## 日本語の折り返し

`word-break:auto-phrase` が文節（「一人の」「担当者が」）で切ってくれる。
Chromeで実際に効いていることは確認済み。そのうえで足りないのが2つある。

**1. 短い見出し・リード文は `pretty` ではなく `balance`。**
`pretty` は最終行しか見ないので、2〜3行の中央寄せだと行の長さがばらついて雑に見える。
`balance` は全行を均そうとする。長文には効かない仕様なので、付けても副作用がない。
対象は `.ttl / .lead / .fv__ttl / .case__ttl / .cta__ttl` など短い塊だけ。
**本文（`.prose p` など）は `pretty` のまま**にすること。

**2. 数字は auto-phrase の対象外。**
「71,000〜96,000円」のような並びは、桁の途中や記号の前後で平気で切れる。
止める方法は `.nw` で囲うか `white-space:nowrap` しかない。
金額を書き足したら**必ず `.nw` で囲うこと**。

`.costbox__v`（別々に通った場合の金額）は `white-space:nowrap` で1行固定にしている。
折らない代わりに、狭い画面では字を小さくして収める（下限20px）。
**この下限を上げると320px級の端末で右にはみ出す。**

### 折り返しの確かめ方

見た目ではなく、実際の行の切れ目を取り出して確認する。
（`<small>` を含む要素は、文字ごとの `getBoundingClientRect().top` がずれて
誤検出するので、行数は要素の高さ÷行高で数えること）

```js
// 390px幅で読み込んでから実行する
function lines(el){
  const w=document.createTreeWalker(el,NodeFilter.SHOW_TEXT);
  const out=[];let cur='',lastTop=null,n;
  while(n=w.nextNode()){for(let i=0;i<n.data.length;i++){
    const r=document.createRange();r.setStart(n,i);r.setEnd(n,i+1);
    const b=r.getBoundingClientRect();
    if(b.height===0){cur+=n.data[i];continue}
    if(lastTop===null||Math.abs(b.top-lastTop)<3){cur+=n.data[i]}
    else{out.push(cur);cur=n.data[i]}
    lastTop=b.top;
  }}
  if(cur)out.push(cur);return out;
}
lines(document.querySelector('#compare .lead'));
```

### 枠が正方形（1/1）である理由

**「ラットプルダウンをしている」と分かるのに必要な範囲が、縦に長いから。**

写真（1023×1537）の中で要るのは **縦24%（トレーナーの頭の上）〜縦80%（お客様が
バーを握る左手）の56%**。ここが入らないと、バーが切れて「ただ座っている写真」になる。

枠も写真も縦位置なので、`cover` で入れると**左右は全部入り、上下だけが切れる**。
枠に残る縦の割合は次の式で決まる。

```
残る割合 = (枠の高さ ÷ 枠の幅) × (1023 ÷ 1537)
        = (枠の高さ ÷ 枠の幅) × 0.666
```

56%を残すには高さが幅の0.84倍以上。**横長の枠では物理的に入らない。**

実際には `aspect-ratio:1/1`（正方形）まで伸ばしてある。0.84でぴったりにしない理由は、
**下辺の斜め切り（`clip-path`）が右下を10%削る**から。ぎりぎりに詰めると、
バーを握る手が斜めに食われる。正方形なら縦20.1%〜86.6%が残り、枠の中での位置は：

| 写したいもの | 元画像の縦位置 | 枠の中の位置 | その位置の斜め切りの線 |
|---|---|---|---|
| トレーナーの頭の上 | 24% | 上から5.9% | — |
| お客様の右手（時計側） | 72% | 78.0% | 90.7% ✅ |
| お客様の左手 | 80% | 90.0% | 97% ✅ |
| バーの左端 | 85% | 97.6% | 99.5% ✅ |

比が固定なので、**どの画面幅でも写り方がまったく同じ**になる。実測（2026/09/01）：

| 画面幅 | 枠 | 残る範囲 |
|---|---|---|
| 320px | 320×320 | 20.1〜86.6% |
| 390px | 390×390 | 20.1〜86.6% |
| 599px | 599×599 | 20.1〜86.6% |
| 768px | 560×560 | 20.1〜86.6% |
| 900px〜 | 560×560 | 20.1〜86.6% |

**やってはいけないこと。**

- **高さを `svh` や固定pxにする。** 画面が低いときや幅が広いときだけ枠が平たくなり、
  そこだけバーが切れる。高さは必ず `aspect-ratio` で幅から出すこと。
- **枠を横長にする（幅を広げて高さを据え置く）。** 同じ理由でバーが切れる。

**幅は写り方に影響しない。** 写り方は `aspect-ratio` と `object-position` だけで決まる。
PCの560pxという値は、純粋に「写真の存在感」と「コピーの位置」の取り合いで決めた数字。

## 掲載内容の出どころ

料金・経歴・資格・FAQ はすべて本家サイト（＝Wix版の実データ）から転記しています。
**勝手に数字や実績を作らないこと。** 不明な値は「公式LINEでお問い合わせください」に寄せます。

- 初回体験 80分 3,300円（税込）／入会金 通常 33,000円（税込）
- 初月のお支払い例は **入会金無料を適用した金額**で計算している。現在は入会金0円のため、初月合計＝月額（37,400円／56,100円）。
  キャンペーンを終了するときは、この2枚のカードを 70,400円／89,100円 に戻し、`sim__after` の「入会金が無料なので〜」の一文も消すこと。
- **ビフォーアフターの写真は本人の許諾済み。**「効果には個人差があり、結果を保証するものではありません」の注記を必ず残すこと（`.ba__note`）。
- ヘッドコンディショニングのビフォーアフター（20代男性・頭のサイズ）は、別サービスで予約URLも違うため**このLPには載せていない**。
- 「1,000名以上」「セッション1万件以上」「ストレッチ継続率9割超え」は代表・奥野個人の実績としてABOUTページに記載のあるもの。ジム全体の実績として書き換えないこと。
- **お客様の声（40代男性）は施主から提供された実際の声**です。本家サイトには未掲載。文面を勝手に脚色しないこと。
- 会員データの円グラフ（年代・入会時の経験・目的）は本家トップと同じ構成比で、**元画像から再現した概算**です。そのため「※構成比は概算です」の注記を必ず残すこと。正確な数値が手に入ったら差し替えます。

## 公開について（未実施）

- `canonical` / `og:url` は `https://www.dlightgym.com/lp/trial/` を仮で入れてあります。
  実際の公開URLが決まったら、`index.html` の以下3か所を実URLに直してください。
  `<link rel="canonical">` / `<meta property="og:url">` / JSON-LD（Service）の `offers.url`
- `og:image` は本家サイトの画像URLを参照しています（`https://www.dlightgym.com/assets/img/hero-home.jpg`）。
  本家と別ドメインで公開する場合は、このLPの `assets/img/hero-home.jpg` の絶対URLに差し替えてください。
- 広告の流入計測をする場合は、`assets/js/analytics.js` 冒頭の `GA_MEASUREMENT_ID` に測定IDを入れるだけで
  予約クリック（`reserve_click` / `generate_lead`）、LINEクリック、FAQ開封、読了率が記録されます。
  空のままなら外部への送信は一切ありません。
